4. What changed in the game, in one page

File Change Why
Assets/Scripts/Core/ReleaseInfo.cs new: Version, BundleId, Engine, Platform, Caption(), BuildLine() one place that reads the build identity from Application.*, so no screen can describe a different build

Assets/Scripts/Editor/Week17ReleasePanels.cs new idempotent builder builds the title controls and both panels in code and saves the scene; re-runnable
Assets/Scripts/Editor/Week17Checks.cs new: TC-REL-01…05 proves the caption, the build line, both panels, the five listeners, and that the panels cannot leak into a match

Assets/Scripts/Editor/A11yAudit.cs RunWeek17() seam the Week 16 log is never overwritten by a Week 17 run
ProjectSettings/ProjectSettings.asset bundleVersion, AndroidBundleVersionCode the release identity

The version is not in productName. On Android, productName decides the save folder under Application.persistentDataPath; moving it would move the profile store and look exactly like a wipe to the player. That is why the identity lives in bundleVersion, which is what Application.version reads, and why TC-REL-01 compares the on-screen caption to Application.version instead of to a string in the scene.

5. What the week found

Two defects surfaced while running the gates, and both are in Evidence/issue_disposition.md with their numbers:

  1. DEF-17-05 - the release-panel builder destroyed VersionLabel and the two panels before rebuilding them, but not the three new title buttons. Its second run therefore left a second HOW TO PLAY, CREDITS and EXIT on top of the first. TC-A11Y-02 reported three controls overlapping themselves; the regression read 26 passed, 1 failed, 1 blocked until the builder was made to clean up after itself. After the fix the panel has eight children, one of each control, and the row reads 27 / 0 / 1.
  2. DEF-17-06 - the release check TC-REL-04 read null where a listener should have been, because it looked at InvokableCall.Target instead of the delegate uGUI actually stores. The wiring was correct; the check was not. It now names all five handlers.

Both are recorded because a log that only shows the final green run cannot tell a reader whether the work was clean or the failures were hidden.

6. What this release does not claim

  • No APK and no handset. adb reports no attached device and no build was produced this week, so the module's "install and run from a clean state" is BLOCKED, and TC-COMPAT-01 stays blocked with it.
  • No device performance, battery or thermal claim. Every measurement in this package came from the Editor.
  • No participant usability study. Week 14 recorded that no participant was available; Week 17 does not invent one.
  • The four not-measurable accessibility rows are unmeasured, not passed: HUDPanel/TurnText and HUDPanel/CountsText are drawn over the board with no opaque backdrop, HUDPanel/PauseButton has no panel behind it, and ProfilePanel/NameInput has no opaque fill of its own.
